# MicroSIP Native Call Labels — модуль исходного кода

**Статус:** исходный код интеграции, НЕ готовый DLL-плагин и НЕ EXE. На Windows/MFC пока не собран и не испытан.

## Зачем

Во входящем окне появляется строка с **label аккаунта** из `MicroSIP.ini` (`[AccountN] label=`). Заголовок становится **Incoming Call - MyCompany** (пример). Caller Name, SIP URI и кнопки ответа остаются на месте. Если label пустой, используется `username@domain` (как в остальном UI MicroSIP через `GetAccountLabel`).

Дополнительно патч **отключает проверку обновлений** приложения (`CheckUpdates` и EOL-напоминания). Иначе MicroSIP предлагает установить более новую официальную сборку, и при установке пропатченный `microsip.exe` затирается.

## Почему не DLL

У обычного MicroSIP нет документированного DLL plugin API для редактирования окна входящего звонка. Поэтому это изменение самого открытого исходного кода, которое после сборки встроено в MicroSIP без фоновых служб/AutoHotkey/DLL-injection.

## Что нужно

1. **Исходники MicroSIP** (файлы `RinginDlg.cpp`, `RinginDlg.h`, `Resource.h`, `res/dialog.rc2`, `mainDlg.cpp`, `microsip.cpp`). Официальные архивы: https://www.microsip.org/source
2. Python 3 на Windows для однократного применения исправления.
3. Visual Studio с MFC/C++ и все зависимости, необходимые для сборки выбранной версии MicroSIP (в частности, PJSIP). На сайте разработчика отмечено, что сторонние библиотеки в исходный архив не входят. Сборка может потребовать настройки окружения.

## Установка в исходники

Сначала закрой MicroSIP и сделай резервную копию папок с действующими экземплярами.

```powershell
py -3 apply_patch.py "C:\Src\MicroSIP"
```

Скрипт правит **исходники**, НЕ меняет запущенные/установленные exe. Создаёт резервные копии `*.call-label.bak` для изменённых файлов. Уже пропатченные файлы пропускаются (можно донакатить отключение обновлений поверх старого call-label патча).

Собери модифицированный MicroSIP из Visual Studio по инструкции к конкретной версии исходников. Затем скопируй новый exe в каждую папку с твоими портативными копиями, сохранив существующие настройки `microsip.ini`. Обязательно проверь совпадение версии и разрядности сторонних библиотек.

Label задаётся в настройках аккаунта MicroSIP (поле Label) и хранится в `MicroSIP.ini`:

```ini
[Account1]
label=MyCompany
```

Отдельный `call-label.ini` не используется.

## Проверка

1. Запусти **модифицированный** MicroSIP.
2. Зарегистрируй SIP-линию; в аккаунте должен быть заполнен Label.
3. Сделай входящий тестовый звонок.
4. Убедись, что видно label аккаунта над именем звонящего, а ответ/сброс работают.
5. Проверь DPI 125–200%, несколько одновременных звонков и работу на твоей версии Windows.

## Отмена

```powershell
py -3 apply_patch.py "C:\Src\MicroSIP" --undo
```

Восстанавливаются исходные файлы из резервных копий. Для возврата к прежней программе просто используй сохранённый оригинальный `microsip.exe`; пользовательский `microsip.ini` не затрагивается.

## Ограничения

- Это **патч к исходникам**, не готовый установщик.
- Сделан по структуре исходников MicroSIP, в частности `RinginDlg.cpp` и `res/dialog.rc2` версии проекта 2024 года. На иной версии пути или фрагменты могут отличаться: скрипт прекратит работу, если не найдёт необходимые шаблоны.
- Нужна сборка с MFC и зависимостями MicroSIP. Нельзя просто положить этот ZIP рядом с обычным `microsip.exe` и ожидать появления метки.
- Сборка и тестирование на Windows с SIP-провайдерами в текущем окружении не выполнялись.
- Показывается label **активного** аккаунта (`accountSettings.accountId`), не отдельный label на каждый одновременный звонок с разных линий.
